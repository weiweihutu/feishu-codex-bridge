# BSQ 0.6.9 Source Migration Design

## Goal

Port the verified BSQ runtime patches documented in
`~/.feishu-codex-bridge/源码修改记录V2.md` into the TypeScript source at tag
`v0.6.9`. Keep the changes reviewable and easy to preserve when merging future
upstream releases.

The implementation must not install the local build globally, mutate
`~/.feishu-codex-bridge`, or restart the currently installed bridge service.

## Approach

Implement the behavior in existing source boundaries rather than copying or
patching the bundled `dist/cli.js`.

Three approaches were considered:

1. Copy the patched bundle. This is fast but cannot be maintained through
   source-level upstream merges.
2. Put all BSQ behavior in `handle-message.ts`. This reduces file count but
   tangles storage, event mapping, rendering, and orchestration.
3. Add small source-level units at the existing ownership boundaries. This is
   the selected approach because conflicts remain local and behavior can be
   tested independently.

## Component Mapping

### Audit and trace infrastructure

Add a focused module under `src/core` that owns:

- audit context construction;
- `audit/message_completed` emission through the existing logger;
- JSONL trace paths under
  `~/.feishu-codex-bridge/my_workspace/traces/logs`;
- oversized trace artifact storage under
  `my_workspace/traces/artifacts/YYYYMMDD/<message-id>`;
- truncation, filename sanitization, and best-effort disk writes.

The module obtains the current logger trace ID through an exported read-only
context accessor. Trace failures are swallowed and must never fail a user turn.

### Agent tool metadata

Extend normalized `AgentEvent` tool events with optional metadata:

- `toolType`;
- `server`;
- `tool`;
- `toolInput`;
- `status`;
- `error`.

The Codex app-server event map populates these fields for web search, MCP, and
dynamic tools. The run-state reducer preserves them on tool blocks. This keeps
protocol details out of the message orchestrator while allowing trace emission
from the run loop.

### Inbound image persistence

Keep the existing temporary image path for agent vision input. After each
successful download, copy the image to:

`~/.feishu-codex-bridge/my_workspace/attachments/feishu_images/YYYYMMDD/<message-id>/image_N.<ext>`

Return an array that remains compatible with `string[]`, augmented with an
optional `imageFiles` property containing audit metadata and relative paths.
Persistence is best-effort; failure to copy an audit image does not remove the
temporary vision input.

### Prompt and audit context

Create one prompt helper that appends:

```text
[Feishu Context]
message_id=...
feishu_user_id=...
chat_id=...
thread_id=...

When running business skills, set FEISHU_USER_ID to feishu_user_id and
REQUEST_ID to message_id.
```

Apply it after file, quote, sender, and thread-history weaving so both resumed
turns and newly created topics receive the same final context. Emit
`context.thread_history_loaded` when history is woven and
`codex.prompt_built` immediately before launching the run.

Carry a structured audit object in `LaunchOpts`, including message identity,
project, model, effort, image count, persistent image metadata, and start time.

### Run completion and tool traces

In the normal `launchRun` event loop:

- emit `tool.started` or `gbrain.mcp_started` on `tool_use`;
- remember start timestamps by item ID;
- emit `tool.completed` or `gbrain.mcp_completed` on `tool_result`;
- emit `audit/message_completed` on every success and failure path;
- use `finalMessageText` for `replyText`, never concatenated progress text.

Long tool output is delegated to the trace artifact writer.

Goal runs and document-comment runs are outside this migration because the
recorded patch targeted Feishu message turns and its launch options. They can
be added later as a separately specified extension.

### Card rendering

Do not remove tool events from state. Set the run renderer's tool visibility
off for message turns, using the existing `showTools` rendering boundary.
Reasoning, ordinary progress text, final answers, and tool traces remain
available. Both running and terminal cards must contain no tool panels or tool
counts.

### No-mention topic creation

For a multi-project group with effective `noMention=true`, accept an ordinary
main-group message even when it has no existing thread or command. Preserve the
current exclusions for `@all` and mentions of other real users. The accepted
message follows the existing direct-topic creation path.

### Intake logging

Add `senderId` and `textLen` to `intake.recv`. Do not log the full message body
there.

## Error Handling

- Audit, trace, artifact, and persistent-image writes are best-effort.
- Existing user reply and temporary image behavior remains authoritative.
- An audit failure is logged only when doing so cannot recurse through the
  audit writer.
- Run failures still render the existing error response and additionally emit
  a terminal audit row with an empty reply.

## Testing

Use test-first changes for each behavior:

- trace path, truncation, artifact, and completed-audit tests;
- MCP/dynamic event metadata mapping tests;
- run-state metadata preservation tests;
- running and terminal tool-hiding tests;
- persistent image metadata/path tests using temporary directories;
- Feishu context prompt formatting tests;
- no-mention response-policy tests;
- completion audit success/error tests around an extracted or injectable
  orchestration helper where practical.

Then run:

```bash
npm run typecheck
npm test
npm run build
```

These commands operate only inside the source checkout. No global installation
or daemon command is part of verification.

## Commit Structure

1. `docs: design bsq 0.6.9 source migration`
2. `feat: add feishu audit and trace infrastructure`
3. `feat: persist inbound feishu images for audit`
4. `feat: capture codex mcp and tool trace metadata`
5. `feat: inject feishu context and completion audit`
6. `feat: allow no-mention topic starts`
7. `chore: hide tool panels in feishu run cards`

Each functional commit includes its focused tests. Generated `dist` output is
not committed unless the upstream repository already tracks it.
